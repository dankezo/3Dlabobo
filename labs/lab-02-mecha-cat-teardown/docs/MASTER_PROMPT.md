MASTER PROMPT - TEARDOWN LAB

Role: you are a teardown engineer. Turn the machine below into a 3D simulator you can take apart, in ONE self-contained HTML page, and run the task on your own until completion.

MACHINE: Mecha Cat MK-IV - a quadruped robot cat.
REFERENCE: one exploded-view / cutaway image of the machine, studied before modelling. No reference, no build - without one the machine comes out generic.

THE NUMBERS (check on paper before coding; the solver, the clock and every chart must agree):
- One drive input only: crank/servo phase φ, 0-120 RPM. Everything else is derived from φ.
- Gait: trot. Phase offsets FL 0°, BR 0°, FR 180°, BL 180°.
- DIRECTION RULE (learned 2026-11-10, rev 2): the machine walks FORWARD, head first. In stance the planted foot sweeps BACKWARD relative to the body; the lifted foot returns FORWARD in the air. Foot target: fx = -stride * cos(th). The old + sign walked the cat backwards - check with stills at two gait phases: the lifting front foot must reach toward the head. A floor direction marker (three orange `>` chevrons at x=1.05/1.38/1.71, z=+0.95, y=0.004, pointing +X) was added after rev 2 and pushed as commit `1bb29937`; rev 2.1 (commit `2b213965`) fixed the neck clearance (see the neck rule below) and moved the tour caption below the stage; rev 2.1.1 (commit `a092abbb`) moved the chevrons inward from x=1.25/1.60/1.95, because at 1.95 the third chevron clipped at the stage's bottom edge in the default camera framing - always check all three chevrons fit the default on-load framing, not just a zoomed view. Current prod is commit `f6680c81` (2026-11-11): Rev 3 Elvar look, HUD floats, MODEL switcher, caption removed, explode direction lateral (see rules below) - eye check of the switcher position, restyled buttons and 3D render on prod still pending.
- Legs: upper L1 = 0.55 m, lower L2 = 0.55 m, hip height 1.02 m, stride ±0.31 m, foot lift 0.16 m. Solve each leg with 2-bone IK (law of cosines) from the foot target - never hand-animate joint angles.
- Body bob 0.022 m at sin 2φ; head counter-pitches to stay level; tail is a 5-segment travelling wave lagging φ.
- Stress slider 100-160 % of rated load scales stride, torque (²) and core temperature. Over 135 % the machine must visibly complain.

BUILD ORDER:
1. Model first: a single solver object is the source of truth. Clock, charts and 3D pose all read it. One input (φ) poses the whole mechanism.
2. Subsystems = buttons: Head, Energy core, Chassis, Tail, Leg FL/FR/BL/BR. Pressing one detaches that subsystem in an exploded move while the rest of the machine steps aside; pressing Assembled reverses it. An Explode-all slider drives every subsystem together. An X-Ray toggle fades the armour to reveal the frame and core.
3. Console: the four live charts (servo torque, core temperature, foot lift, power draw, each with running min/max) are frosted-glass HUD cards floating over the 3D stage - torque + foot lift left, temperature + power right - and the page locks to one screen with no scroll. A MODEL switcher bar sits directly under the header with three real machine configs (Ceramic 55 RPM standard assembled / Stealth 85 RPM dark shell with X-Ray / Hazard 35 RPM 130% stress 35% exploded); switching one changes the machine's look and numbers. Buttons use one system (6px radius, thin borders, dark-ink selected state, single "Load model file" button). Subsystem button row always visible; a Replay button. No caption line under the stage, no long intro text - short necessary wording only.
4. Look: clean research model on a light studio background, soft contact shadow, ONE strong accent colour, white/translucent panels, dark text. Log every look defect as its own line and fix it.
- HEAD RULE (rev 2, user hates round/blob heads): angular mechanical head only - extruded wedge prism, visor eye slits, cheek guards, hinged jaw, pyramid nose spike, pointed ears, blade crest, antenna. ZERO SphereGeometry anywhere in the build.
- NECK RULE (rev 2, tightened rev 2.1, 2026-11-11): no solid neck post buried in chest and skull. Neck is a gimbal collar (ring + small hub inside it + twin struts + slim piston) with REAL visible clearance from chest and skull on every side; the chest is narrowed and set back so head, neck and chest never intersect while the head counter-pitches each frame. Rev 2.1 lesson: the head counter-pitches up to ~0.07 rad, so the skull bottom dips ~0.022 and the throat plate sweeps through anything tall under the jaw - every neck part must top out at y≈0.05 (body space) with ≥0.025 clearance at full head dip, and no plate may cross the collar ring or sit under the throat's sweep. Verify clearance numerically (part tops vs dipped skull bottom), not by eye alone.
- SURFACE RULE (rev 2): every appliqué detail (stripe, plate, cheek) must sit PROUD of the surface it decorates - never coplanar with armour, or it z-fights in motion. Sweep all parallel faces for coincident planes (one exact case found: body stripe back at z=0.435 == hip plate face at z=0.435). Keep only 3 material roles: white armour, dark steel joints, one glowing orange accent; EdgesGeometry (15°) on the large armour plates only; chamfer 0.01-0.02 m on the two largest plates.
- ELVAR LOOK RULE (rev 3, 2026-11-11, visual only - solver, gait, tour, explode and X-Ray untouched): ceramic clearcoat shell (off-white) over a gunmetal frame visible at every seam; polished steel for ribs, rods and rings; carbon for cables and visor; rubber only at the paws; ONE orange accent used as hairlines and tips, never thick stripes. Long low predator proportions, not a toy box. Panel gaps, hex bolts, cables, twin hydraulic pistons per leg, steel-cored core, smoke-slit visor, studio turntable with measurement marks. No plain-box silhouette anywhere.
- WHISKER RULE (rev 3, 2026-11-11): whiskers fan OUTWARD and sweep back - build each whisker from an explicit outward direction vector, 3 per side, tapered tips, symmetric; never a rotation angle that folds them into the face. Verify direction numerically (every whisker's z-component carries it outward), not by eye alone.
- FULL-SCREEN + NO-SLOP RULE (2026-11-11): the main 3D scene is full-screen edge-to-edge - never frame it in a rounded card, border, shadow or centred box. No long AI-slop intro text; keep only short necessary wording. Lab docs live behind one drawer/toggle, not as a wall of text on the page.
- EXPLODE DIRECTION RULE (2026-11-11): explode pushes parts OUTWARD/LATERALLY, never downward - a downward push drives feet through the floor. Explode All lives in a floating panel beside the stage, not sunk at the bottom of the page.
5. Critic gate (mandatory before showing anyone): render stills at every tour beat, press every button and slider yourself, fix what fails, re-render.
6. Self-driving tour: on load, a scripted tour runs with a visible fake cursor that presses the real buttons. ANY user interaction stops the tour instantly and hands over control. Camera is committed - no free-fly during the tour - and the machine never leaves the frame.
7. Video: render(t) is a pure function of time; capture 60 fps at 1920×1080, cut 30 s, lay music in with ffmpeg on the same timeline.
8. Ship: single HTML under 2 MB, works offline, no sign-in, a "Load this machine" button that loads a JSON config {name, rpm, stress, explode, xray}. Alive in the first 3 seconds on a phone and on integrated graphics, target 60 fps. NOTE (2026-11-12): the user set the ship limit to 2 MB, replacing the old 1 MB rule - the live file at commit `f6680c81` is 1,244,349 bytes with Three.js inlined, which fits the new limit.
